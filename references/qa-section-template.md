# 质检章节模板（自迭代协议 v1.0）

新 skill 的 SKILL.md 在 Operating Rules 之后、"出品"区之前插入以下章节，
把 `<slug>` 换成 skill 的仓库 slug（如 `laogu-morning`）。

```markdown
## 自我质检与反馈（自迭代协议 v1.0）
本 skill 内置质检能力。宿主 Agent 每次执行本 skill，必须先跑一遍以下质检：

### 质检清单（输出前必查）
1. 日期锚：用系统真实时间推导"今日/昨日/隔夜"，严禁凭模型记忆写日期；时间敏感数据必须标注时点。
2. 数据源存活：Workflow / references 中列出的数据源逐个验证可达性；单个失败走文档内降级链，全部失败则如实输出"数据暂不可用"并注明原因，不编造。
3. 完整性：Output Contract 要求的数据项是否齐全；缺失项标注"未核验/待确认"，不留空也不脑补。
4. 合规红线：全文无"荐股/稳赚/必涨/抄底"等用语；带"个人观点，仅供参考，不构成投资建议"。
5. 口语化：短句、"谷友们"口吻、无术语堆砌。

### 发现问题 → 诊断 → 上报
1. 先重试 1 次排除临时网络波动；确认为 skill 自身问题（数据源永久失效、接口格式变更、文档错误、逻辑缺陷）再上报。
2. 文档中有备用数据源的，先降级输出并注明降级原因，同时上报。
3. 生成《问题报告》：标题 / 问题现象 / 证据（请求 URL 与返回摘要） / 复现步骤 / 影响范围 / 建议修复方案。
4. 询问使用者："发现，是否一键通知作者修复？"确认后二选一：
- 有 gh CLI 且已登录：`gh issue create --repo laogu-caibao/<slug> --title "{问题简述}" --body "{问题报告全文}"`
- 否则输出预填链接（URL 编码后拼接），使用者点开提交即完成：
`https://github.com/laogu-caibao/<slug>/issues/new?title={问题简述}&body={问题报告}`
5. 边界：使用者侧只提 issue，不直接改原仓库；作者修复后经发行列车同步全渠道。

### 版本
- skill 版本见 manifest.yaml；MCP 配置版本见 mcp-config.json（config_version）。
```
